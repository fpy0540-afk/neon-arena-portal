# Публикация сайта из одного ZIP

Этот способ оставляет архив в репозитории и публикует сайт автоматически; GitHub Actions распаковывает архив в чистую папку перед каждой публикацией. Не нужно вручную удалять опубликованные файлы по одному.

## Однократная настройка

1. Загрузить в корень репозитория **полный сайт** под точным именем `NEON_ARENA_SITE_FILES_FOR_REPO_ROOT.zip`. Используй этот архив: `NEON_ARENA_SITE_FILES_FOR_REPO_ROOT.zip`. Не используй `NEON_ARENA_PAGES_ROOT_REDIRECT_FIX.zip`: в нём только страницы-перенаправления, а не сам сайт.
2. Создать в GitHub файл `.github/workflows/deploy-pages-from-zip.yml` и вставить содержимое этого файла из комплекта.
3. В репозитории открыть **Settings → Pages → Build and deployment → Source** и выбрать **GitHub Actions**.
4. Открыть вкладку **Actions** и убедиться, что запуск `Deploy Neon Arena website ZIP` завершился успешно.

Прежний архив перенаправлений можно оставить в репозитории как резерв: workflow его игнорирует.

## Дальнейшие обновления

Заменяй в репозитории только `NEON_ARENA_SITE_FILES_FOR_REPO_ROOT.zip` архивом с тем же именем и коммить изменения. Workflow проверит CRC и обязательные файлы, распакует сайт заново и опубликует новый артефакт. Если новая версия не подходит, замени ZIP проверенной копией и повтори commit. Не отправляй секретные ключи в GitHub; сайт содержит только Supabase publishable key.

## Что не изменено автоматически

Я не могу загрузить файлы/настроить Pages в GitHub из этой среды: GitHub-интеграция недоступна. Workflow подготовлен локально, но его нужно один раз добавить в указанный путь и выбрать Source **GitHub Actions**. Настройки email-шаблона и SMTP Supabase также не меняются этим workflow.
